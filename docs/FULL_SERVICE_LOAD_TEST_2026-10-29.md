# 말모아 전체 기능 혼합 부하 테스트

> 실행일: 2026-10-29
>
> 환경: 별도 Node.js 부하 프로세스 → Spring Boot → PostgreSQL 16.15(WSL)

## 이번에 추가한 시나리오

기존 Heartbeat·위치·심박수 3종에 실제 서비스 기능을 추가해 한꺼번에 호출했다.

| 영역 | 포함한 기능 |
|---|---|
| 사용자 기기 | Heartbeat, 위치, 심박수, AAC 카드판 조회, 카드 발화 기록 |
| 사용자 상태 | 표정 결과, STT 결과, 긴급 모드 |
| 보호자 화면 | AAC 카드판, 최신 위치, 장소, 루틴, 알림 조회 |
| 개인화·분석 | AI Context 생성, 보호자 리포트, PDF 리포트 |
| 실시간 연결 | SSE 연결 유지 |

각 가상 사용자는 별도 AAC 사용자, 기기 Token, 보호자 계정과 카드를 사용했다. 보호자 API는 `APP_LOAD_TEST_ENABLED=true`에서만 활성화되는 테스트 전용 인증으로 호출했으며 기본값과 운영 환경에서는 비활성화된다.

500명 단계에서는 요청 오류는 없었지만 P95가 임시 기준 500ms를 넘었다. 최대 응답시간은 4.81초였고 Hikari DB 연결 10개를 모두 사용했다. 리포트 조회 P95는 약 3.07초, STT P95는 약 1.31초였다.

따라서 단순 텔레메트리만 측정한 결과와 달리 실제 기능을 섞으면 현재 구성의 안정 구간은 500명보다 낮다. 다음 시험에서 250명·350명·400명 단계를 추가해 통과 상한을 좁힌다.

1,000개 SSE 연결을 30초 동안 유지하는 단기 시험은 통과했다. 다만 실제 이벤트가 계속 발행되는 상태, 재연결 폭주, 10분 이상 장시간 연결과 네트워크 단절 복구는 아직 별도 시험이 필요하다.

## 아직 실제 연동 전이라 제외한 항목

- 실제 AI Provider 문장 추천: 현재 Provider 인터페이스만 있고 외부 AI가 연결되지 않음
- 실제 Push 발송: 구독·알림 저장은 구현됐지만 외부 Push Provider 전송은 별도 연동 필요
- 실제 음성 파일 처리: 현재 STT 결과 텍스트만 저장하며 음성 파일은 서버로 보내지 않음
- 이미지 대용량 업로드: 파일 크기와 저장소 정책이 확정된 뒤 별도 용량 시험 필요

## 결론

이번 시험부터는 텔레메트리 3종만이 아니라 말모아의 핵심 사용자·보호자 기능을 섞어 측정한다. 현재 결과는 **100명 혼합 부하는 통과**, **500명은 오류는 없지만 응답 지연으로 실패**, **SSE 1,000개 단기 연결은 통과**다.

원본 결과는 Git에서 제외되는 `target/load-test-results/full-service`와 `target/load-test-results/sse`에 저장된다.
